Measured with Knitting `0.1.77`.

Each call sends a value to a worker that returns it unchanged. The measured
time covers encoding, transport and decoding in both directions. All binary
values contain 1 KiB.

## What the runs show

- **Batching improves throughput.** With 100 primitive calls in flight,
  Node.js and Bun process 2–6× as many calls per second as with one at a time.
- **Deno’s single calls have higher overhead.** Its primitives take roughly
  ten times as long as on Node.js and Bun. With 100 calls in flight, their
  cost per call is close to Node.js.
- **Errors cost the most.** `Error` is the slowest type on every runtime at
  both batch sizes.
- **Binary views vary by runtime.** With 100 calls in flight, `Uint8Array`
  takes about half the time of `Float64Array` on Node.js; Bun favors `Float64Array`.

These differences exceeded the spread between runs.

## Run it yourself

The suite lives in
[`knitting-vs-tokio-bench`](https://github.com/mimiMonads/knitting-vs-tokio-bench):

```bash
git clone https://github.com/mimiMonads/knitting-vs-tokio-bench
cd knitting-vs-tokio-bench
npm install
npm install knitting@0.1.77
node scripts/bench.mjs types
node scripts/tables.mjs
```

Each run writes a directory under `results/`. To update this page, commit the
new runs in the bench repo, then copy them into the docs:

```bash
npm run bench:sync -- ../knitting-vs-tokio-bench <runId...>
```
